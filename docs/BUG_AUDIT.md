## New safeguards tested during implementation

- The migrations execute in PostgreSQL (PGlite), including RLS under `anon` and `authenticated` roles, not merely regex checks against SQL text.
- Revision columns and stable game IDs cannot be rewritten by browser clients. Stale revisions match no rows and are surfaced as conflicts rather than recreating deleted games.
- Comment author/name/timestamp columns cannot be spoofed through browser inserts. SQL rejects whitespace-only text, including tabs/newlines, not just literal spaces.
- Secret/service-role keys are rejected even when a valid publishable key is also present.
- Browser tests cover preview/mobile navigation, blocked storage, progress persistence/reset, spoiler resets, authentication, note persistence/isolation, new game publishing, failed saves, image uploads, and configured connection failures. Supabase HTTP responses are mocked, not claims of a hosted end-to-end test.

## Verification results

- Clean lockfile install completed; lint, application/tooling typechecks, and production build passed.
- **75 unit/component/PostgreSQL tests passed.**
- **12 Chromium browser tests passed**, including mobile layout and the real SDK with mocked Supabase HTTP responses.
- Seed consistency and `git diff --check` passed.
- `npm audit`: **0 advisories** at verification time (21 in the initial lockfile).
- An intentionally fake privileged build key was rejected before bundling. The live read-only preview returned HTTP 200 for an Arena-style host and loaded without JavaScript runtime errors.
- The build emits two harmless upstream Zod comment-annotation warnings; Rollup removes those comments. No application lint/type errors remain.

## Remaining boundaries / deployment work

1. **Hosted verification:** real Supabase Auth email delivery, recovery redirects, project settings, PostgREST, and Storage service behavior still require the owner's project. PGlite tests use minimal managed-schema stubs; they do not run GoTrue or the Storage service.
2. **Local-only progress:** checkboxes and spoiler preferences are intentionally not account-synced. They depend on the browser retaining its storage; unavailable storage is visibly reported.
3. **Legacy content:** old base64 assets and invalid `text`-only steps are not automatically migrated. Back up the original browser entry, repair/recreate the records, and upload images before publishing.
4. **Abuse/moderation:** bounded notes, deletion controls, and a basic cooldown are not comprehensive anti-spam. Deleting a recent note or using multiple accounts can bypass the cooldown. Production SMTP/rate limits are project configuration; CAPTCHA needs a frontend widget/token implementation before enabling it.
5. **Asset lifecycle:** the public bucket is not suitable for private files. Discarding a draft or deleting a game leaves potentially shared images intact; clean up orphaned objects deliberately.
6. **Content updates:** public content refreshes on load/retry; notes have manual pagination. Realtime subscriptions, multi-admin draft merging, browser history/deep links, cloud progress, and offline publishing are not implemented.
7. **Verification scope:** tests improve confidence, but do not prove the absence of every bug or replace a full security/accessibility review. Re-run the checks and hosted smoke tests before release.
